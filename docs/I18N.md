# Internationalization (web)

The web UI is prepared for translation (D-088). Only English ships
today; adding a language is a catalog file, not a code change.

## Pieces

| File | Role |
|---|---|
| `web/src/lib/i18n/messages/en.ts` | Source catalog. Every key lives here first. |
| `web/src/lib/i18n/locales.ts` | Registry: code, native name, direction. |
| `web/src/lib/i18n/core.ts` | Pure mechanics: lookup, `{param}` interpolation, CLDR plurals, locale resolution, pseudo-localization. |
| `web/src/lib/i18n/i18n.svelte.ts` | Runtime state: active locale, `t()`, `Intl` formatters, `<html lang dir>`. |
| `web/src/lib/i18n/catalog.test.ts` | Fails on a locale with missing/extra keys, a changed `{placeholder}`, a plural without `{count}`, or code calling `t()` with an unknown key. |
| `web/scripts/i18n-report.mjs` | `npm run i18n:report` — lists text that still bypasses `t()`. |

No dependency: `Intl.PluralRules`, `Intl.NumberFormat`,
`Intl.DateTimeFormat`, `Intl.RelativeTimeFormat` and `Intl.ListFormat`
cover plurals and formatting in every supported browser.

## Writing UI text

```svelte
<script lang="ts">
	import { t } from '$lib/i18n';
</script>

<button aria-label={t('nav.palette')}>{t('palette.action.scan')}</button>
<p>{t('settings.staged.count', { count })}</p>
```

- **Every** user-visible string goes through `t()`: text, `aria-label`,
  `placeholder`, `title`, `alt`, toasts and error fallbacks.
- **Keys name the place**, not the words: `settings.interface.language`.
  Group by screen or component.
- **Whole sentences** with placeholders; never concatenate fragments
  (`'Last scan ' + time` breaks word order in other languages).
- **Counts** are plural messages: `{ one: '{count} file', other:
  '{count} files' }` and `t(key, { count })`. Numbers in params are
  formatted for the locale automatically.
- **Dates, numbers, lists**: `formatDate`/`formatRelative` in
  `$lib/utilities/format`, or `i18n.formatNumber/formatDate/formatRelative/formatList`.
  Never `toLocale*String(undefined)` or hand-built `"3 h ago"`.
- **Direction**: use logical Tailwind utilities (`ms-*`, `me-*`, `ps-*`,
  `pe-*`, `start-*`, `end-*`, `text-start`) instead of `ml/mr/left/right`
  in new code, so right-to-left languages mirror correctly. Content
  direction that is not UI direction (the manga reader's page order)
  stays explicit.
- Brand and technical tokens (Lain, HLS, `Ctrl+K`, key chords) stay
  literal inside the message.
- Keyboard chords (`g p`) are stable across languages on purpose.
- Settings keyword aliases in `lib/settings/sections.ts` stay English:
  they are extra search terms, the translated label is always searched.

## Adding a language

1. Add `{ code: 'pt-BR', name: 'Português (Brasil)', dir: 'ltr' }` to
   `LOCALES` in `locales.ts`.
2. Copy `messages/en.ts` to `messages/pt-BR.ts` and translate the
   values, keeping keys and `{placeholders}`; add plural categories the
   language needs (`few`, `many`…).
3. `npm test` — the parity test tells you what is missing.

Catalogs other than English are loaded on demand (one chunk each);
missing keys fall back to English per key, with a dev-console warning.

## Choosing the language

Settings → Profile → Interface → Language. "System" follows the
browser (`navigator.languages`, exact tag first, then base language).
The choice is stored in this browser. `?locale=<code>` overrides it for
one page load without saving.

## Pseudo-locales (finding gaps)

- `?locale=en-XA` — every translated string is accented, ~35% longer
  and wrapped in `⟦…⟧`. Plain English on screen = a string that still
  bypasses `t()`; clipped text = a layout that will break in German.
- `?locale=ar-XB` — the same, right to left, to check mirroring.

Both are listed in the language picker in dev builds only.

## Migration status

The shell is migrated: navigation, account menu, boot screen, the
settings rail/breadcrumb/staged bar, the Ctrl+K launcher and the
language picker. The rest is migrated screen by screen; track it with:

```sh
npm run i18n:report                 # counts per file, worst first
npm run i18n:report -- --list src/routes/settings   # every finding
```

Server-side messages (API `error` strings) are English and out of scope
for this slice; the web should prefer stable error codes when it shows
a translated message.
