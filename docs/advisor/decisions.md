## Full pluginization

- `D-074` — The reserved Matrix component-mode slice opens now (user instruction 2026-09-25: "quero o lain pluginizavel por completo"); this lifts D-009's reservation for Matrix work only — other reserved slices stay reserved. External providers run as supervised child processes reached over a unix socket, `lain plugin-run` is the in-binary component adapter, the manifest shape in `internal/matrix` is the provisioning unit, and `core.Provider.Invoke(cap, input)` stays the semantic contract. In-process built-ins remain the default bindings; component-mode is an additional provider kind any capability can swap to, not a required topology.
- `D-075` — The trusted-core boundary is confirmed unchanged under full pluginization: auth (D-005), bbolt/`internal/kv` (D-004), the stdlib `net/http` gateway (D-003) and the registry/composition authority stay fixed. "Everything is a plugin" means every functional decision above the core sits behind a capability **and every declared binding is load-bearing**: catalog reads/writes and userstate reads route through the registry so `lain.catalog.*@1`/`lain.userstate.*@1` swaps actually take effect (today the gateway bypasses them via concrete `s.cat`/`s.ustate`).
- `D-076` — The remaining gateway policy islands become versioned capabilities with default providers: Omarchy theme derivation (D-020/D-037), metadata enrich orchestration, localplay supervision (mpv/VLC spawn + measured progress, D-072), library watch (fsnotify debounce/trigger, D-068), admin backup and the transcode settings store (D-045). Each ships as a documented `docs/CONTRACTS.md` capability; gateway handlers thin to registry calls.
- `D-077` — External component provisioning is a watched directory `<data-dir>/plugins/`: the operator drops an `<id>.json` manifest plus its executable; boot discovers and registers, and a runtime watch installs/removes components live through the same Swap/Withdraw authority. No install API and no upload endpoint. Source: user answer, 2026-09-25 grill.

## Familiar player controls

- `D-070` — External playback is available from the web UI and the CLI, as the user specified on 2026-09-23. The browser offers mpv and VLC through an opt-in local `lain://play` handler installed on the browser's machine. The link carries server origin, item ID and player choice only; the local CLI supplies its own saved login, matches the origin, uses the existing direct stream and progress endpoints, and adds no server API or dependency. `lain watch` keeps mpv as default and accepts `--player vlc`; VLC progress must be measured, never inferred from process exit. This leaves the separate desktop client and its libmpv path unchanged (D-013/D-015). Source: user clarification and advisor triage, 2026-09-23.
- `D-071` — Preferred playback language belongs to the user account, shared by web and CLI (Q-039). Add an optional `preferred_language` to the public user shape and an authenticated self-service preference update; existing clients remain compatible. Select matching audio first; when that audio is present, keep subtitles off. Otherwise select a subtitle in the preferred language when the source provides one, with explicit manual track choices still available. Untagged or unavailable tracks fall back to the existing player default. Player choice stays local to each device (D-070); no new dependency. Source: user answer to Q-039, 2026-09-23.
- `D-072` — A natively running server may spawn mpv/VLC itself when the browser sits on the same machine. `GET /api/localplay` advertises usable player binaries only to loopback peers without forwarding headers (a proxy hop means the loopback peer is the proxy, not proof the viewer is local); `POST /api/items/{id}/play-local` launches the player on catalog `file_path`s — no token or stream URL crosses a link — and supervises measured progress into userstate in-process under the authenticated account. Series resolve through the ordered episode list (D-056) skipping missing entries (D-068); one local playback at a time (409 when busy); server shutdown reaps the player. Docker and remote deployments report an empty capability and refuse the POST, so the honest fallbacks remain the web player and the `lain://` handler (D-070). The mpv progress Lua script is shared between CLI and server through `internal/localplay`. Source: user proposal and approval, 2026-09-23.
- `D-073` — An admin may delete an episode's file from disk from the title page's episode grid (Q-040/A): `DELETE /api/items/{id}` under `requireAdmin` removes the catalog item's `file_path` from disk; the entry itself is never hard-deleted — it becomes `missing` per D-068 (progress and metadata preserved, restored if the path returns), which the handler asserts itself rather than waiting on the watcher, since `LAIN_WATCH=0` installs must converge too. The web grid gains a selection mode (toggle per card, clear, select-watched via `progress.completed`) that does not capture the cards' play navigation; delete asks confirmation and runs per selected item. Regular accounts keep no delete affordance, matching the uniform `requireAdmin` mutation pattern. Source: user answers to Q-040, 2026-09-25.


- `D-066` — Replace D-061's terminal-style micro-labels and always-visible session telemetry with familiar playback controls for nontechnical viewers: readable sentence-case title/back navigation, play/pause, explicit ten-second skip controls, volume, time, settings and fullscreen. Group speed, quality, audio, subtitles and optional effects in an in-player settings panel; technical playback information remains available through progressive disclosure. Preserve the host's semantic Omarchy palette (D-020/D-037), overlay geometry and idle fade, and picture clicks that only reveal controls (D-064/D-065). An open settings panel pins the controls and Escape closes it. Existing playback/session, episode, and shader contracts remain unchanged. No dependency is added. Source: explicit user request for a modern, standard player for nontechnical users retaining Omarchy style, plus advisor `answered`, 2026-09-21.
- `D-068` — Files deleted from disk are reconciled in near real time and retained as `missing`, not hard-deleted. (1) Freshness: a `github.com/fsnotify/fsnotify` recursive watcher per library root — the fourth justified dependency (pure Go, no cgo; it carries `golang.org/x/sys` transitively). Debounced events trigger a per-library rescan through the existing `lain.ingest.scan@1` pipeline, so deletions, additions and D-019 move reconciliation all ride the same tested path. Filesystems where inotify never fires (network mounts) keep the manual scan; `LAIN_WATCH=0`/`--watch=0` disables the watcher. (2) Semantics: additive `CatalogItem.missing` (omitempty); a clean scan marks absent files missing instead of pruning them and clears the flag when the file returns — `ScanStats` gains `missing`/`restored` counts while `pruned` stays for compatibility but scans no longer emit it. Hard deletion still happens on library removal; a retention policy for long-missing items is a future question. Two correctness fixes ride along within existing contracts: the playback plan stats `file_path` and answers `available:false` + reason when the file is gone, and an identify failure marks the candidate's path-derived ID present so a transient error never reads as a deletion (D-011). Source: user answers Q-036, 2026-09-22.
- `D-067` — The player owns the keyboard while it is mounted (D-066). A focused button or link keeps Space and Enter as its own activation keys, while the letter and arrow shortcuts still reach the player, so clicking a control never disables them; the seek bar's arrows seek five seconds and Space toggles playback instead of nudging its tenth-of-a-second step grid, and every other slider keeps its own keys. Escape never leaves the episode: it closes the settings panel, then a fullscreen notice, then puts the chrome away, and leaves the chrome up while a wait, a failure or a banner is asking for attention. A fullscreen request the browser refuses or does not offer is reported through a visible, dismissible notice while playback continues windowed. Source: controls/fullscreen audit of the familiar-controls slice plus advisor `answered`, 2026-09-21.

## Stack and build

- `D-001` — Prefer the Go standard library. The only three justified dependencies are `golang.org/x/crypto` for bcrypt, `golang.org/x/term` for login, and `go.etcd.io/bbolt` for `lain.db`. A new dependency is a permanent cost and must be discussed first. Source: `AGENTS.md:6`.
- `D-002` — No cgo and no large C-transpiled dependencies. Builds must remain measured in seconds. Source: `AGENTS.md:20`.
- `D-003` — Use standard-library `net/http` method patterns without an HTTP framework. Source: `AGENTS.md:14`.
- `D-004` — Store data in bbolt through `internal/kv` using JSON values and composite keys in the `users`, `libraries`, `items`, `progress`, and `meta` buckets. Keep `internal/store` only for operator configuration and legacy import. Source: `AGENTS.md:15`.
- `D-005` — Use HS256 JWT in `internal/auth`, implemented with standard-library HMAC/SHA-256 and live role, liveness, and password-version checks. Source: `AGENTS.md:18`.

## Boundaries

- `D-006` — Plugins implement `core.Provider` and never touch `net/http`, process-global state, or another plugin's files. Source: `AGENTS.md:33`.
- `D-007` — Media bytes never enter plugin calls; the gateway streams from disk. Source: `AGENTS.md:35`.
- `D-008` — Catalog owns identity and userstate owns progress; never merge them. Source: `AGENTS.md:36`.
- `D-009` — The `merge-many` and `fan-out` modes belong to the metadata slice and must not be repurposed early. Transcode, metadata daemon, and Matrix daemon work begin only in their explicit slices. Source: `AGENTS.md:28`.

## Hygiene and discipline

- `D-010` — Never commit real release-group, fansub, tracker, indexer, or site names. Use fictional placeholders such as `[Fansub-A]`, `[Fansub-B]`, and `tracker-example`. Anime titles are allowed; group identities are not. Source: `AGENTS.md:42`.
- `D-011` — Use typed errors with stable `core.Error` codes; never panic on bad input and never fail silently. Source: `AGENTS.md:26`.
- `D-012` — Work in small slices and keep `go test ./...` green for behavior changes. Source: `AGENTS.md:24`.
- `D-013` — This repository is the server; the desktop client lives in `projects/lain-desktop`. Do not mix their commits. Source: `AGENTS.md:68`.
- `D-014` — English is the only canonical repository language for code, comments, tests, plans, project documentation, contributor instructions, and wikis in both repositories. Non-English content is limited to explicitly identified translations, localization resources, and language-specific documentation variants. Source: interview 2026-09-11.
- `D-069` — RESCINDED 2026-09-23: mutation testing (go-gremlins) is removed from the repository practice — `tools/mutation/`, the `// mutation-clean` markers, the AGENTS.md gate and the per-`*_test.go` requirement are gone. The user's hardware cannot absorb the run cost; the practice returns only on explicit request after a hardware upgrade. Original text: Mutation testing is a repository practice: `go-gremlins` pinned at v0.6.0, installed via `go install` outside go.mod (dev tool, not a build dependency — D-001 untouched; same category as ffmpeg/Node per D-023/D-034/D-036). Scope is every package's non-test code including `cmd/lain`; packages with no tests get minimal behavior suites first. Every mutant must be resolved: LIVED and NOT_COVERED both count as surviving — strengthen the tests or cover the code; equivalent mutants are recorded in `tools/mutation/state.json` with a one-line justification, never silently skipped (D-035 honesty). The manifest keys each package to a hash of its `.go` sources plus the tool version, so an unchanged clean package is skipped instead of re-verified; verified test files carry a `// mutation-clean` marker comment. New or changed tests require a mutation run of their package before commit (`AGENTS.md` Workflow). Run artifacts stay local/gitignored like qa reports (D-035). Source: user answers Q-037, 2026-09-22; rescinded by explicit user instruction 2026-09-23.

## Transcode evolution

- `D-028` — Add asynchronous transcoding as `lain.playback.transcode@2` while retaining the synchronous `@1` contract and GET endpoint. Playback inspection is side-effect free and reports an opaque session plus `idle|queued|running|ready|failed`; only an authenticated POST starts or joins work, and an item-scoped status endpoint exposes state without filesystem paths. Source: user answer Q-017/A + advisor triage, 2026-09-13.
- `D-029` — Bound ready transcode artifacts with a plugin-private 20 GiB LRU cache, configurable by `--transcode-cache-size` / `LAIN_TRANSCODE_CACHE_SIZE`. Metadata uses atomic sidecars; cleanup runs at startup and around admission/completion, excludes active artifacts, and removes stale-source and abandoned-temporary entries without coupling the plugin to library deletion. Source: user answer Q-018/A + delegated engineering choice + advisor triage, 2026-09-13.
- `D-030` — Browser compatibility becomes probe-driven and applies equally to anime, movies and series: direct-play only verified web-safe streams; otherwise produce one conservative SDR H.264/AAC MP4, with selected stream identity in the session/cache key. Add selectable audio first, then convertible text subtitles as WebVTT sidecars; reject HDR and unsupported subtitle tracks explicitly until separately scoped tone-map/burn-in profiles. Source: user-delegated engineering choice Q-019 + advisor triage, 2026-09-13.
- `D-031` — Keep progressive MP4 with HTTP Range as the delivery protocol. HLS/DASH, ABR ladders and hardware acceleration stay deferred; future hardware support must be explicit operator opt-in with capability probing and visible software fallback, never silent opportunistic switching. Source: user-delegated engineering choice Q-020 + advisor triage, 2026-09-13.

- `D-039` — `lain.playback.transcode@2` gains one additive status field, `progress` (0..1, omitempty), present while a job runs; no version bump and no server-side ETA promise — the client derives elapsed time and pace from deltas. The field is additive but the @2 payload had been fixed by D-028, so it ships only under this explicit answer. Source: user answer Q-027/A, 2026-09-17.
- `D-040` — The AV1 wait is not paid by weakening the frozen profile: `web-mp4-sdr-v2` / `veryfast` / software-only stays exactly as D-030/D-031 fixed it. The wait is instead reserved to its own slice, authorized but not started: browser-capability direct play, where the client reports decoder support and a verified source remuxes (AV1/Opus into MP4 plus a WebVTT sidecar) instead of re-encoding. That slice needs its own plan before any code. Source: user answer Q-028/C, 2026-09-17.
- `D-041` — Preparation stays play-triggered: only the player's authenticated POST starts work (D-028 intact); no details-page CTA and no proactive warm after scan. Source: user answer Q-029/A, 2026-09-17.

- `D-047` — Close the last gaps found in the second audit pass, still inside the approved `@3` shape: (a) on-the-fly subtitle extraction — `@3` gains a `subtitles` action and a sidecar-only delivery kind, so `GET /api/items/{id}/subtitles?stream=N` serves WebVTT for a **directly played** file without transcoding it (Jellyfin's "allow subtitle extraction on the fly"), gated by the new `allow_subtitle_extraction` setting (nil/absent = on, explicit false → `forbidden`); image-based tracks stay `unsupported-media`. - `D-048` — The gateway signs HLS media URIs, not the plugin: serving `index.m3u8` rewrites the `EXT-X-MAP` URI and every segment line to carry `session` and the caller's `token`. - `D-050` — Two Jellyfin-documented hardware options complete the D-046 surface, with no frozen payload touched: `hardware_device` (default `/dev/dri/renderD128`) names the VA-API render node and feeds both the capability probe and the `-hwaccel_device` argument, so a host whose render node is not the default can use its GPU; and `rkmpp` joins the backend list, matching Jellyfin's documented acceleration methods (VA-API, NVENC, QSV, AMF, V4L2, VideoToolbox, RKMPP). Source: audit against Jellyfin's transcoding docs, 2026-09-18.
- `D-051` — The visible software fallback must clean the burn-in filter graph too: `softwareFallback` stripped `hwupload`/`format=nv12` from `plan.filters`, but the image-subtitle path bakes those tokens into `plan.complexFilter`, so a VA-API session that both burns in an image subtitle and fails its hardware attempt retried with the hardware upload chain and failed again. Source: audit of the D-049/D-050 pass, 2026-09-18.
- `D-052` — Independent adversarial subagent passes over the plugin, gateway, browser player, contracts and coordinator lifecycle found and fixed a series of real defects without touching any frozen payload: an HLS session longer than the v1-era one-hour preparation deadline was killed and had its directory deleted under the player (HLS now runs on an unbounded context, ending by finish/cancel/idle); a second start wiped live sessions' directories under a configured temp path (the orphan sweep now excludes active sessions and claims the shared root with an `.owner` marker); the persisted `queue_size` was a no-op (admission now adopts it); a client-supplied out-of-range segment index paused ffmpeg permanently (the gateway records a position only for a segment that exists, and an out-of-range index means caught-up); a cached-ready HLS session was replayed as progressive and 409'd (the player learns the delivery and attaches hls.js); and a per-user policy was bypassed by cached sessions, by joining a live session, and by the v1 compatibility path (all three now re-check the policy, and a capped account is downgraded from direct play to a capped transcode). Every fix carries a regression test; the client-side one was proven by reverting it. Source: adversarial audit passes 1–8, 2026-09-18.
- `D-053` — Three Jellyfin-documented options complete the encoding surface, additive and inside the `@3` shape (no frozen payload touched): `hls_segment_container` (`fmp4` default, CMAF with an init segment; or `mpegts`, classic `.ts` with no `#EXT-X-MAP`), `hardware_low_power` (QSV's low-power H.264/HEVC encoder, honoured only by QSV), and the AV1 preset now reaches the argv (it was exposed and validated but hardcoded). `TranscodeProfileKey` gained the output-affecting inputs it was missing — `hardware_decode_codecs` and `ffmpeg_path` — while the VA-API render device stays operational and out of the key (D-045/D-050). Everything is probed with a real ffmpeg where the local build allows it. Source: Jellyfin feature-parity audit, 2026-09-18.
- `D-054` — Hardware (VPP) tone mapping is **deliberately not implemented**, and the gap is documented in `docs/CONTRACTS.md` rather than shipped unverified. Concrete evidence from the local ffmpeg: `vpp_qsv` exposes **no `tonemap` option** (only deinterlace/denoise/detail/procamp/crop/scale), so Jellyfin's QSV chain (`vpp_qsv=tonemap=1`) cannot work here regardless; and `tonemap_vaapi` needs VA-API device/frame plumbing (`-init_hw_device`/`-filter_hw_device`, or hwaccel-surface frames) that cannot be validated without a device (the probe finds no backend on the dev host). A wrong chain would fail at runtime and then hit the same fallback-stripping pitfall as D-051 (the software retry must replace the hardware filter, not replay it). The software `zscale`+`tonemap`/`libplacebo` chain already produces correct SDR output, so the missing feature is speed, not correctness. Source: user mandate "all features" + the honest-limitation discipline, 2026-09-18.
- `D-055` — Three corrections close the last documented gaps of the D-042 transcode slice; none touches a frozen payload or the `@3` shape. (a) The served HLS playlist dropped the `#EXT-X-DISCONTINUITY` ffmpeg wrote — the parser even attributed it to the *previous* segment, where HLS places it *before* the segment that starts the new timeline — so a client could stitch across a timestamp jump; the tag is now attributed to the following segment and re-emitted between segments (and dropped when segment deletion moves that boundary to the front of the playlist, where nothing precedes it to be discontinuous from). (b) `position` was a high-water mark, so after a rewind ffmpeg kept racing ahead and the deleter removed the very segments the client was about to re-fetch; the latest report now wins, matching Jellyfin's use of the reported playback position. An out-of-order report can only make the position older, which errs toward pausing sooner and keeping more segments — never toward deleting or racing ahead of the viewer, so the ordering robustness the high-water mark bought is not lost. (c) The browser direct-play profile accepted only AAC audio inside MP4; MP3 is equally web-safe and now direct-plays too, while AC-3/E-AC-3 stay excluded because Chromium on Linux cannot decode them (D-030's "verified web-safe streams"). Each fix carries a regression test that was proven to fail with the fix reverted. Hardware (VPP) tone mapping stays deliberately unimplemented per D-054. Source: user instruction "faça as correções" on the reported gap list, 2026-09-19.
- `D-056` — The web UI becomes title-centric. `/item/{id}` was a page for one file, which is wrong for anything episodic: it is now the *title* page (hero, poster rail, season filter, episode grid), and a single-file title keeps the plain item page. `/player/{id}` is the watch page — video with the title's episodes beside it — and the route reloads when the id param changes instead of once in `onMount`, so switching episodes cannot leave the previous episode's state or its marker on screen (the smoke asserts the in-place switch, and that assertion fails with `onMount`). The grid is served by a new additive read, `GET /api/catalog/{id}/episodes` → `{items}`: chosen over reusing `GET /api/search` (Q-033/A) so a detail page never depends on the search plugin, and implemented on the concrete catalog service the gateway already uses for `Page`/`Get`, leaving the `lain.catalog.read@1` capability untouched. - `D-057` — The player's seek bar spans the media, and a seek past what the encoder has written starts producing there. Root cause, verified in the hls.js source and the MSE spec: an `EVENT` playlist lists only the segments ffmpeg has already written, so hls.js sets the MediaSource duration to that edge (`buffer-controller.getDurationAndRange`, with `liveDurationInfinity` as the only escape) and, per MSE §10.1, `seekable` becomes `[0, duration]` — i.e. the produced prefix. A 24-minute episode therefore showed a 0:37 timeline. The fix has three parts, each at the layer that owns the fact: (a) the gateway adds `duration_sec` to the plan response from the probe it already runs — the same fact Jellyfin's `PlaybackInfo` exposes as `RunTimeTicks`, placed on the HTTP view so `lain.playback.plan@1` and every plugin shape stay frozen; (b) the player hands that length to hls.js through the supported `attachMedia(media, {overrides: {duration}})` (a public `MediaOverrides` field), which makes the element's duration and seekable cover the episode — safe mid-session because `endOfStream` is driven by the playlist's `ENDLIST` (`BUFFER_EOS`), never by the duration; (c) a target outside the session's own range rebuilds it at the target through `start_sec`, the mechanism a resume and a track change already use, while a target inside the produced range stays an ordinary instant element seek. The produced edge is read from hls.js on demand (`latestLevelDetails.edge`) rather than mirrored in state. The buffered region is drawn in source coordinates, so a resumed or re-seeked session no longer paints its ready range from zero. Proven in a real Chromium against a deliberately lagging transcode (a VP9 source, one thread, `veryslow`: a copy-compatible H.264 source finishes before a viewer could seek, which is why the first attempts could not reproduce it) — `seek bar spans 600.0s of a 600.0s episode` and `dragged past the produced edge: rebuilt at 420.0s and played on from there`, each shown to fail with its own part reverted (`media duration 2s`, and a session that was never rebuilt). The user delegated the placement decision (Q-034); this is the layering a senior would pick and the one that keeps the plugin contracts frozen. Source: user report "o controle (slider) do player só está mostrando o tempo do buffer" + web research into hls.js/MSE, 2026-09-19.
- `D-058` — A browser that reports what it can decode gets the file as it is. Direct play was a hardcoded container rule (D-030), so every Matroska file was transcoded on principle and a seek paid the session restart D-057 measured. Measured on this host (Chrome 152, through the gateway's existing `video/x-matroska` + `ServeContent` path): H.264+AAC Matroska opens, seeks in 93–268 ms and downloads ~11 KB of a 13.8 MB file, cues at end included; HEVC+AAC opens too — and paints nothing (no error event, an advancing clock, `videoWidth` 0x0, zero frames). The two a-priori queries disagree in opposite directions: `decodingInfo` is right about HEVC and AC-3 but false-negatives VP9+Opus, which in fact plays; `canPlayType` with a codec string cannot see a platform decoder it has no string for. So the client probes a fixed matrix once per page load, reports the **union** of both answers as tokens (`mkv`, `mkv/h264`), and the planner requires the container *and* every track a player would select to be covered. The pairing is the part that carries the weight: a flat codec list would let "HEVC decodes in MP4" license "HEVC in Matroska", which is exactly the measured black screen. `PlanRequest.Capabilities` is additive and optional — nil reproduces the old rules byte for byte, which is what the desktop, `curl` and the existing Go tests still exercise — and the gateway validates tokens against its own vocabulary, so a client cannot widen what the planner reasons about. A claim also cannot raise the H.264 High-10 floor: `canPlayType` answers "probably" for the profile bits it does not parse, so the probed pixel format decides there. Trust stops at the plan: on a `direct` plan the player demands a decoded picture within ~3.2s and falls back to a transcode at the viewer's position, saying why. Proven in a real Chromium — a new smoke step direct-plays a procedural H.264/AAC Matroska and seeks to its midpoint in **126 ms** (one Range request, against 2.6 s for the rebuild in the same run), the same file answers `direct`/`transcode` for four different claims including one naming another codec family, and a client that lies about HEVC gets a picture back instead of a black screen. Both halves were shown to be load-bearing by reverting them: with the frame check off, the lying-client step fails with "timed out waiting for the frame check started a transcode"; with the codec pairing off, the partial claim plans `direct` for an HEVC file at the wire and the suite breaks downstream. Source: user direction that 2026 browsers decode Matroska natively (with sources) + the measured matrix, 2026-09-19.
- `D-059` — The web player owns a dependency-free WebGPU shader engine, while the browser media element remains authoritative for demux, decode, buffering, seeking, A/V sync and audio (D-043/D-057/D-058 stay intact). Each decoded frame is re-imported as a `GPUExternalTexture`, normalized once into an internal `rgba16float` `GPUTexture`, processed by an ordered WGSL-native graph with explicit inputs, up to eight scalar parameters, reusable hazard-safe texture slots and `requestVideoFrameCallback` scheduling, then displayed on a canvas. WebGPU is optional: native video remains visible until the first GPU submission and takes over on initialization/runtime failure or while a browser-rendered sidecar subtitle is active. Anime4K is a future MIT-attributed shader pack, never an engine dependency; the first slice uses only original ingest/display/no-op WGSL and adds no package or server/API contract. User-facing presets, custom shader loading and settings wait until the runtime is proven. Source: user direction + advisor `answered`, 2026-09-19.
- `D-060` — With D-059 proven, ship the first opt-in shader pack as `Anime4K DoG x2`: four ordered WGSL passes (luminance, horizontal Gaussian/min-max, vertical Gaussian/min-max, bounded correction at 2x) adapted from the MIT-licensed Anime4K/anime4k-wgpu sources, with source headers and complete notices retained. The player exposes only `Off` (default) and this conservative preset; no persistence, arbitrary-file loading or advanced effects UI enters this slice. The pack remains isolated from the generic engine and adds no runtime dependency or server/API contract. Source: user direction + advisor `answered`, 2026-09-19.
- `D-082` — D-059's mechanism for "subtitles stay visible and correct while the canvas presents frames" is amended: instead of pausing the renderer while a browser-rendered sidecar is active, the track runs in `hidden` mode and the player paints `activeCues` itself in a DOM overlay over the canvas, honoring cue `line`/`position`/`align`/`size` on the letterboxed picture rect and stacking unpositioned cues at the bottom; with the renderer off, `showing` restores native `::cue` rendering. The invariant holds — the media element still owns demux/decode/seek/A-V/audio, and a sidecar that fails to load makes the renderer yield to native video, preserving D-059's original degradation (D-011). Chosen over burn-in, which would force `copyVideo` off and re-encode sessions that today remux in seconds, and over surfacing the incompatibility, which under D-071 would leave effects unusable for exactly the users whose preferred language auto-selects a subtitle. Same change fixes the HLS `has_subtitle` staleness: the first-play status loop now raises `hasSubtitle` whenever the session reports the extracted sidecar, so a preferred-language subtitle no longer silently never displays on first play. Web-only, no dependency, no contract change. Source: user report that Anime4K never engages in Brave + advisor `answered`, 2026-10-02.
- `D-062` — The admin Playback page becomes an operational control center without changing `TranscodeSettings` or any server contract: at-a-glance delivery/engine/HDR/session status, section navigation and search put common decisions first; capability diagnostics and expert resource/hardware controls use progressive disclosure but remain reachable and visibly marked when configured. `Apply Auto` stages a conservative software-safe policy using only existing values (`hls`, `fmp4`, `auto`, `0`, empty/inherit) and never saves by itself. ## Lain list (external tracking)

- `D-078` — The "lain list" is a per-user media tracking list independent of local files: entries are standalone records (title, media type, status, progress, score, dates, cover, remote identity) that exist with or without library media, so manga, comics and other non-played types live in the same list as anime, movies and series. It is a third domain beside catalog and userstate and never merges into either (the D-008 boundary extended): catalog owns file identity, userstate owns playback progress, the list owns what the user tracks. v1 entries are import-sourced only; manual entries and linking entries to catalog items are later slices. Source: user answers, 2026-09-28 grill.
- `D-079` — External list platforms link to the existing local account; they are never sign-in methods (local identity stays per D-005). A link stores a per-user access token server-side — a credential that is never logged (D-026) and never leaves the server. Each platform is adopted only when it offers a fast, secure, official integration; platforms without one are skipped by design. Unlinking a platform removes its token and its imported entries, which the platform owns. Source: user answers, 2026-09-28 grill.
- `D-080` — AniList linking uses the OAuth2 authorization-code grant (no PKCE exists in AniList's flow; tokens are year-lived JWTs with no refresh). The operator registers one AniList OAuth application and enters client id/secret as server settings under admin (never in code or binaries; `LAIN_ANILIST_CLIENT_ID`/`LAIN_ANILIST_CLIENT_SECRET` may seed them), with the exact callback URL shown in the admin UI. The flow is `GET /api/me/links/anilist/authorize` → anilist.co → `GET /api/auth/anilist/callback`; `state` is an HMAC-signed, expiring nonce bound to the local user id, so the callback needs no session storage. Source: user answers, 2026-09-28 grill.
- `D-081` — Import is remote-authoritative over platform-owned entries and runs on connect, on demand (`POST /api/me/links/{platform}/sync`), and on a fixed-interval server ticker (~6h, not operator-configured this slice). An entry absent from the remote response is removed; a dead or revoked token marks the link `token-state` while entries stay visible. Source: user answers, 2026-09-28 grill.
- `D-083` — AniList linking gains a zero-setup path beside D-080's operator app: **auth-pin with the authorization-code grant**. An official "Lain" application (AniList client 52227, registered once by the maintainer) uses AniList's own pin page as its redirect; its client id AND client secret ship compiled into the binary — extractable by design, as with every distributed OAuth client (Taiga, Kometa ship theirs in public source). The implicit grant was the original plan but AniList rejects `response_type=token` with `unsupported_grant_type` for console-created apps (all are "confidential" clients with a secret) — verified live 2026-10-07 — so the pin page returns an authorization *code* that `POST /api/me/links/{platform}/code` exchanges with the embedded credentials; pasted URLs/fragments are normalized. The embedded secret cannot be kept secret in principle (any binary can be extracted); the accepted risk is brand spoofing on the consent screen and a mass revocation killing only the pin path — D-080's operator-app redirect flow stays available and is preferred when configured. Source: user direction 2026-10-07 ("é isso que eu quero, o Auth-pin" / "foda-se, toma").
- `D-084` — Scrobble: finishing an episode can push progress back to a linked platform. It is a new op (`LinkPushInput`/`LinkPushOutput`) on the existing `lain.listlink@1` rather than a new capability, so composition and bindings are untouched and providers decline with the usual typed codes. It is opt-in per account (`LinkedAccount.Scrobble`, `PATCH /api/me/links/{platform}`, default off) because it writes to the user's remote list. Conservative by design: it fires only on the not-completed → completed transition of a progress write, only advances an entry the user already tracks (exact normalized-title match, ambiguous matches skipped), never regresses progress or reopens a completed/repeating entry, skips season > 1 (platforms list seasons as separate entries) and movies, and runs off the request path. The stored entry is updated after a successful push so the next finish compares against what the platform holds; the next sync stays remote-authoritative (D-081). Authorized by the user directly; no advisor was available.
- `D-085` — Comics and manga are in scope: D-016's "personal video" scope is widened to add a reading slice, on explicit user instruction (2026-09-30; music, audiobooks, photos and live TV stay out). Library types `comic` and `manga` scan `cbz`/`cbr`/`cb7` archives (`pdf` is not read); the catalog kinds are `comic` and `manga`, chosen from the library type, which `Candidate` now carries additively (`library_type`). A volume is stored as Season and a chapter or issue as Episode, each 0 when the file does not carry it. Page indexing is a new capability, `lain.comic.pages@1` (exactly-one, `lain-comic-archive`), and composition v8 puts `lain-identify-comic` ahead of the anime parser, which accepts everything. Page bytes never cross the plugin boundary: the provider returns the index and the gateway streams a page from the archive (`GET /api/items/{id}/pages`, `/pages/{n}`); `cbz` is read with the stdlib, `cbr`/`cb7` through an operator-installed `bsdtar` or `7z` (same category as ffmpeg, D-023) and degrade to a typed error without one. No dependency is added. Reading progress reuses the progress record: `position_sec` is the 1-based page and `duration_sec` the page count. The reader is one engine (`ReaderBase`) with two adaptations, `MangaReader` (right-to-left, spreads with the cover alone, webtoon strip, per-title direction) and `ComicReader` (left-to-right, single page, fit and zoom, opt-in spreads, continuous scroll), because the two are read differently. Source: user instruction 2026-09-30.
- `D-086` — Audience and profiles. Lain's audience is technical users (developers, self-hosters), not the general public; every UI flow must be fully keyboard-operable (focus-trapped modals, a key per action, keys shown in the UI), recorded in `AGENTS.md`. Accounts gain a public profile: display name (≤40 chars), bio (≤160), and an avatar that is either an uploaded picture (PNG/JPEG/GIF/WebP, ≤2 MB, ≤4096 px per side, validated by content and stored as `<data>/avatars/<user id>`, never in the account record) or one of eight pre-made mascots (ids validated server-side, artwork in the web client). Routes: `PATCH /api/me/profile`, `PUT`/`DELETE /api/me/avatar`, `GET /api/users/{id}/avatar` (signed-in, `?token=` allowed), `GET /api/profile/mascots`. The server-status "online" indicator is removed from the navigation. Source: user instruction 2026-09-30.
- `D-087` — Settings information architecture. Settings split into YOU (Profile, Playback, Connections, Security) and SERVER (Libraries, Users, Transcoding, Integrations, Plugins, Backup) in a fixed two-pane rail; the admin page formerly called Playback is **Transcoding** (`/settings/transcoding`) and `/settings/playback` is the personal page (player, language, video effects). `/settings` reopens the last section; the list-link OAuth callback lands on `/settings/connections`. Save model: YOU applies on change with an inline "saved" mark; SERVER stages changes behind one bar (Ctrl+S apply, Esc discard). Keyboard: `g`+letter per section (mnemonic, role-independent), `[`/`]`, `j`/`k`, and a global Ctrl+K launcher over sections, every setting row (`web/src/lib/settings/sections.ts`), actions (scan, add library/user, backup, sign out) and library titles. Transcoding opens in Auto (summary) and reveals every section in Custom or on search/jump. Separators and fields use palette-independent `hairline`/`field` tokens derived from the foreground, because several Omarchy palettes map surface onto the background. Scanning is an action (Ctrl+K, `S` on Library, header status only while running), not a setting. Source: user instruction 2026-09-30.
- `D-088` — Web internationalization is prepared, not translated: an in-house, dependency-free i18n layer (`web/src/lib/i18n`) with a typed English source catalog, dotted keys, `{param}` interpolation, CLDR plurals and date/number/relative/list formatting through the browser's `Intl`, lazy per-locale catalogs with per-key English fallback, `<html lang dir>` kept in sync, and a per-browser language choice ("System" follows `navigator.languages`). Pseudo-locales `en-XA` (accented, longer) and `ar-XB` (right to left) expose untranslated text, truncation and mirroring. CI enforces catalog parity (keys, placeholders, plural shape) and that every literal `t()` key exists; `npm run i18n:report` tracks remaining hard-coded text. The shell is migrated; screens migrate incrementally. No second language ships yet and server messages stay English. Source: user instruction 2026-09-30.

## Acquisition slice (accepted 2026-10-04)

Proposed as `A-1`…`A-16` in `docs/slices/acquisition.md` (branch `feat/acquisition`); accepted by the user on 2026-10-04 with the defaults as written, plus one condition on cleanup (D-112). `A-n` is `D-(107+n)`.

- `D-108` — No new dependency for acquisition: the BitTorrent engine, bencode, HTTP/UDP trackers, the Torznab/Newznab client and the parser-socket client are standard library only (D-001, D-002). Measured before asking: anacrolix/torrent would roughly triple the cold build (23 s → ~65–70 s), add ~19 MB to the binary and ~150 modules. DHT, or any library for it, is a new decision before any code. Source: A-1, user answer 2026-10-03.
- `D-109` — Engine scope v1: BitTorrent v1 `.torrent` and magnets (BEP 9 over BEP 10), HTTP and UDP trackers (BEP 15/23), pipelined 16 KiB requests, SHA-1 verification, resume from a persisted bitfield with recheck, seeding with an inbound listener. Not in v1: DHT, PEX, uTP, encryption, v2/hybrid, web seeds — trackerless magnets are refused with an explanation. The engine is core code (`internal/torrent`), not a plugin, because it moves bytes and owns goroutines (D-006/D-007, D-090). Source: A-2.
- `D-110` — Download clients are an interface (`acquire.DownloadClient`); the native engine is the first implementation and qBittorrent/Transmission adapters may follow without touching import. Source: A-3.
- `D-111` — Disk is reserved up front against the shared download limits (D-092): a grab reserves the torrent's full size (`max_bytes` budget plus `min_free_bytes` floor) before any byte is written, counting the HTTP download manager's usage too; a magnet is checked when its size becomes known. Overruns fail with `quota-exceeded`/`disk-full`. Torrent data counts while it exists on disk. Source: A-4.
- `D-112` — Seeding is bounded and configurable: stop at ratio 1.0 or after 24 h, whichever comes first, then delete the torrent copy (defaults; both limits 0 = no seeding). Rate caps and peer limits are settings. **Condition:** cleanup never removes or unlinks a library file — hardlinked, moved in place, or lying inside a library root — and refuses a download folder that is, contains or lies inside a library; every deletion goes through one guarded path, proven by `internal/acquire/cleanup_test.go`. Source: A-5, user approval and condition 2026-10-04.
- `D-113` — Release parsing is `lain.release.parse@1` (ordered-many, first accepted): `lain-release-model` asks the installed lain-parser over `<data-dir>/parser.sock` (`LAIN_PARSER_SOCKET` overrides); `lain-release-tokenizer` is the fallback and the source of technical tags. A missing or failing model declines, never fails. Source: A-6.
- `D-114` — Indexers are `lain.indexer@1` (ordered-many, `unsupported-protocol` declines, the D-080/listlink pattern); `lain-indexer-torznab` speaks Torznab and Newznab, so direct indexers and Jackett/Prowlarr work. Definitions persist in acquisition storage; the API key travels in the contract input, is never logged (D-026), never returned (`has_api_key`), and errors name the host only. Source: A-7.
- `D-115` — Per-indexer rate limit (minimum interval, default 2 s) before each request; health is a `t=caps` probe whose result and last error are stored on the indexer. Source: A-8.
- `D-116` — Every acquisition route is admin-only (the D-091 rule): it contacts remote hosts and writes to disk. Source: A-9.
- `D-117` — Import is parse, match, place, rescan: media files (video, or cbz/cbr/cb7 for reading libraries; samples skipped; a movie is its largest video) are parsed, matched to an existing library title first, placed by hardlink when possible (copy across filesystems), copy while seeding or move when not, and the library is rescanned. Existing files are never overwritten. Source: A-10.
- `D-118` — Naming scheme v1, chosen so Lain's identifiers read every imported name back as the same title and numbers (`TestImportedNamesRoundTrip`): `Title/Season NN/Title - SNNEMM.ext` (multi-episode `SNNEMM-EKK`); absolute anime is season 0, `Title/[Group] Title - MMM.ext` with a known group, else `Title/Title - S00EMM.ext`; movies `Title (Year)/Title (Year).ext`; manga/comics `Title/Title v01 c001.cbz`. Source: A-11.
- `D-119` — Acquisition buckets (`acq_indexers`, `acq_grabs`, `acq_settings`, `acq_torrents`) are declared in `internal/kv/acquire.go` and created by their owner; `kv.Open` is not edited (D-004). Source: A-12.
- `D-120` — Acquisition tests never touch the network: swarms, trackers and indexers are in-process on loopback with generated bytes and placeholder names (D-010). Source: A-13.
- `D-121` — Phase 2 automation stays out of Phase 1 contracts; the grab record carries the parsed release, quality and target so monitoring, upgrades and blocklists build on it. Source: A-14.
- `D-122` — The engine always listens: `listen_port` 0 picks a free port at each start (default 51413; forward it behind NAT), `LAIN_ACQUIRE_LISTEN_PORT` seeds it on first boot, and a busy port falls back to a free one with a log line. Acquisition never blocks server start; its routes answer 503 if it cannot start. Source: A-15, user approval 2026-10-04.
- `D-123` — Usenet is searchable, not downloadable: Newznab results are shown and marked; grabbing one is refused with `unsupported-protocol` until an NZB client is decided. Source: A-16, user approval 2026-10-04 (stays deferred).

## Acquisition automation, Phase 2 (accepted 2026-10-04)

Proposed as `A-17`…`A-27` in `docs/slices/acquisition.md`; accepted by the user on 2026-10-04. `A-n` is `D-(107+n)`. The `MetadataRecord` change for per-season episode lists and air dates stays deferred (D-032 unchanged).

- `D-124` — Monitored titles are the unit of automation: library, kind (the library type), title and aliases, quality profile and numbering, in their own bucket `acq_monitored`. They never write the catalog (D-008); what a library has is read from catalog items by title key every time. Source: A-17.
- `D-125` — "Wanted" needs no new metadata contract: expected numbers come from an explicit range, else the title's metadata episode total (D-134), else "newer than the highest present" for ongoing titles. Missing = expected − present; movies are wanted until a file exists; manga and comics track chapters or volumes. Per-season lists and air dates stay out until the user specifies a `MetadataRecord` change (D-032). Source: A-18.
- `D-126` — Quality profiles (`acq_profiles`): ordered allowed resolutions, allowed sources, a cutoff, preferred and blocked groups, blocked words, size bounds per unit, minimum seeders and a proper/repack preference; a default profile (720p+, upgrade to 1080p) exists from first use. Source: A-19.
- `D-127` — One decision engine judges every candidate (manual search, RSS, automatic search): parse → title/number fit → profile accept/reject with reasons → score. Manual search shows rejections; automation grabs only accepted releases, best score first, never twice for the same unit. Source: A-20.
- `D-128` — Upgrades run until the profile cutoff. Files an upgrade replaces are moved out of the library into `<dir>/replaced/<grab>/`, put back if placing the new files fails, never deleted automatically, and purged only by an explicit admin action (the D-112 spirit: Lain never destroys a library file on its own). Source: A-21.
- `D-129` — Blocklist (`acq_blocklist`) by info hash and title: a download that fails or stalls (no progress for `stall_hours`, default 6) is blocklisted and removed through the D-112 path; a release whose import fails is blocklisted but keeps its data for a manual retry. Automation never grabs a blocklisted release; entries can be cleared. Source: A-22.
- `D-130` — Schedules are settings: RSS sync every `rss_minutes` (default 30, minimum 10; a query-less Torznab read honouring D-115), missing search every `search_hours` (default 12, 0 = on demand only). Automation is off until enabled. Source: A-23.
- `D-131` — Anime numbering is `absolute` or `seasonal`; a season map (`season → first absolute episode`) converts both ways, split cours are further seasons in the map, and release-group preference lives in the profile. Source: A-24.
- `D-132` — Automation never exceeds the budget: automatic grabs go through `Grab`, so through the D-111 reservation and queue slots; a full budget pauses automation with a visible reason. Source: A-25.
- `D-133` — Quality ledger: because Lain's names carry no quality (D-118), each import records `library path → resolution` in `acq_quality`, independent of the queue; upgrade checks read it before the file name, so automation never re-grabs what it already has. Source: A-26.
- `D-134` — Metadata episode totals are cached on the monitored title (`metadata_episodes`) and refreshed when it is searched, so computing what is wanted never calls the network; tests stub the lookup (D-120). Source: A-27.

## Acquisition subtitles, Phase 3 (accepted 2026-10-05)

Proposed as `A-28`…`A-45` in `docs/slices/acquisition.md`; accepted by the user on 2026-10-05. `A-n` is `D-(107+n)`. No new dependency; `MetadataRecord` (D-032) and the frozen playback/transcode shapes are untouched.

- `D-135` — Sidecars are found by name, never by content scan: `<media basename>[.<lang>][.forced|.sdh|.hi].<srt|ass|ssa|vtt>` in the media's folder. Language tags (ISO 639-1, 639-2 B/T, region forms like `pt-BR`) fold to one ISO 639-2 code (D-071's form); unknown tags read as `und`. Sidecars are not catalog items; they are read from disk when asked. Source: A-28.
- `D-136` — Players get sidecars through additive routes, not the frozen playback plan: `GET /api/items/{id}/sidecars` (any signed-in user) and `GET /api/items/{id}/sidecars/{n}` (WebVTT; SRT/VTT converted in Go, ASS/SSA reduced to plain-text cues). Source: A-29.
- `D-137` — Subtitle providers are `lain.subtitle@1` (ordered-many, `unsupported-provider` declines) with the account in the contract input (the D-114 pattern): secrets never logged or returned (`has_*` flags), errors name the host only. First provider: `lain-subtitle-opensubtitles` (OpenSubtitles.com REST, the operator's own API key, base URL a setting so tests use a local fake). Source: A-30.
- `D-138` — Matching prefers the file's OpenSubtitles moviehash (size + 64 KiB head + tail, stdlib), then the parsed title/season/episode; video only. Source: A-31.
- `D-139` — Wanted subtitle languages live on the quality profile (`subtitle_languages`, ISO 639-2, ordered; empty = no subtitle automation) with the audio rule (D-145) and `subtitle_hi` (`include`/`prefer`/`exclude`). A language is present when an embedded stream, a sidecar or, under the audio rule, a matching audio stream has it, read through `lain.media.probe@1`, never guessed from names. Source: A-32.
- `D-140` — Sync check before placing: a subtitle with no cues, whose last cue ends more than 10 % (and at least 2 min) past the media's end, or whose first cue starts after the end is refused and recorded (D-147). No automatic retiming in v1. Source: A-33.
- `D-141` — Text is normalized to UTF-8 without a dependency: UTF-8 (BOM stripped) and BOM-marked UTF-16 via the stdlib, anything else read as Windows-1252. Other legacy encodings would need `golang.org/x/text`, a separate dependency decision. Source: A-34.
- `D-142` — Placement and ownership: a fetched subtitle is written as `<basename>.<lang>[.forced|.sdh].<ext>` next to the media, never over an existing file (D-117); Lain records what it wrote in the `acq_subtitles` ledger. Replacing or removing a sidecar moves it to the D-128 holding folder (`replaced/subtitles/`); library files, sidecars included, are never deleted automatically (D-112). Source: A-35.
- `D-143` — Subtitle automation reuses Phase 2: for files of monitored titles, after each import and every `subtitle_hours` (default 24, 0 = on demand), the best accepted subtitle per missing language is fetched. Manual search and fetch work for any video item. Admin only (D-116). Source: A-36.
- `D-144` — Probe-dependent behavior is unit-tested with an injected probe; the real ffprobe path is covered by a gated test behind `-tags e2e`. Source: A-37.
- `D-145` — The audio rule is stored inverted: `subtitle_even_with_audio` (default off) instead of D-139's `subtitle_skip_if_audio` (default on), so profiles saved before Phase 3 decode to the D-071 default with no migration. Source: A-38.
- `D-146` — An item is governed by the profile of the monitored title in the same library whose title or alias matches, else the default profile. Manual search may name languages explicitly (`?languages=en,pt-BR`; the panel's languages field). Source: A-39.
- `D-147` — Unknown duration (probe failed) skips the sync check and places the file; a file with no readable cues is always refused. Refusals are kept per provider file id in `acq_subblock` with the reason, media and time; automation never takes a refused file again until an admin clears it (Acquire › Subtitles, one or all). Source: A-40, amended 2026-10-05 when clearing was built.
- `D-148` — Ranking: hash match +1000, same release group +100, same resolution +20, same source +20, hearing-impaired under `prefer` +30, plus 5·log2(downloads+1). Forced subtitles, wrong-episode/season answers, unwanted languages, HI under `exclude` and refused files are shown but rejected (the D-127 pattern). Source: A-41.
- `D-149` — The web player lists sidecars in its subtitle menu, auto-selects one only where D-071 wants subtitles and no embedded track matches, never auto-selects a forced one, and plays it as a `<track>` in every mode: choosing a sidecar never rebuilds a transcode and is never burned in. Source: A-42.
- `D-150` — OpenSubtitles session: the API key alone unless a username is set, then one login with the token kept in memory for 12 h per account. `por` asks for `pt-br` and `pt-pt`, `zho` for `zh-cn` and `zh-tw`. The core fetches download links with a 5 MiB cap; the provider never touches the library. Source: A-43.
- `D-151` — Keys: `t` opens the subtitle panel (on a Wanted row, and on an item page for its file or every file of the title); inside it Enter searches a file or takes a subtitle, `f` fetches every missing language (monitored titles), Del on a sidecar moves it to the holding folder after a confirm, `l` edits the languages, Backspace goes back. Acquire › Subtitles (`5`) lists refusals (Del clears one, Shift+C all) and the ledger. Source: A-44, extended 2026-10-05.
- `D-152` — Subtitle provider accounts are managed like indexers and profiles: each change applies at once from its own dialog, outside the Ctrl+S staging bar (as D-087 already treats list items). Source: A-45.
