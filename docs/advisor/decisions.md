# lain server decisions (citable in plans)

Use these IDs in plans and advisor calls: `D-001`, etc.
Update this file when the user answers a `needs-user` question.

## Stack and build

- `D-001` — Prefer the Go standard library. The only three justified dependencies are `golang.org/x/crypto` for bcrypt, `golang.org/x/term` for login, and `go.etcd.io/bbolt` for `lain.db`. A new dependency is a permanent cost and must be discussed first. Source: `AGENTS.md:6`.
- `D-002` — No cgo and no large C-transpiled dependencies. Builds must remain measured in seconds. Source: `AGENTS.md:20`.
- `D-003` — Use standard-library `net/http` method patterns without an HTTP framework. Source: `AGENTS.md:14`.
- `D-004` — Store data in bbolt through `internal/kv` using JSON values and composite keys in the `users`, `libraries`, `items`, `progress`, and `meta` buckets. Keep `internal/store` only for operator configuration and legacy import. Source: `AGENTS.md:15`.
- `D-005` — Use HS256 JWT in `internal/auth`, implemented with standard-library HMAC/SHA-256 and live role, liveness, and password-version checks. Source: `AGENTS.md:18`.

## Boundaries

- `D-006` — Plugins implement `core.Provider` and never touch `net/http`, process-global state, or another plugin's files. Source: `AGENTS.md:33`.
- `D-007` — Media bytes never enter plugin calls; the gateway streams from disk. Source: `AGENTS.md:35`.
- `D-008` — Catalog owns identity and userstate owns progress; never merge them. Source: `AGENTS.md:36`.
- `D-009` — The `merge-many` and `fan-out` modes belong to the metadata slice and must not be repurposed early. Transcode, metadata daemon, and Matrix daemon work begin only in their explicit slices. Source: `AGENTS.md:28`.

## Hygiene and discipline

- `D-010` — Never commit real release-group, fansub, tracker, indexer, or site names. Use fictional placeholders such as `[Fansub-A]`, `[Fansub-B]`, and `tracker-example`. Anime titles are allowed; group identities are not. Source: `AGENTS.md:42`.
- `D-011` — Use typed errors with stable `core.Error` codes; never panic on bad input and never fail silently. Source: `AGENTS.md:26`.
- `D-012` — Work in small slices and keep `go test ./...` green for behavior changes. Source: `AGENTS.md:24`.
- `D-013` — This repository is the server; the desktop client lives in `projects/lain-desktop`. Do not mix their commits. Source: `AGENTS.md:68`.
- `D-014` — English is the only canonical repository language for code, comments, tests, plans, project documentation, contributor instructions, and wikis in both repositories. Non-English content is limited to explicitly identified translations, localization resources, and language-specific documentation variants. Source: interview 2026-09-11.

It follows the live Omarchy palette from the server host through a public, read-only endpoint that returns only validated semantic colors and mode; all browsers share that palette, and deployments without Omarchy retain the built-in fallback. Source: user answers Q-001 and Q-002, 2026-09-11.
- `D-021` — Before selecting the next WebUI direction, create an isolated static showroom under `web/design-showcase/` with ten distinct, non-binding HTML concepts and one comparison index. Source: user answers Q-003 and Q-004, 2026-09-11.

Preserve the current hero selection policy (resume first, otherwise recently added), Continue Watching landscape cards, Recently Added, and one rail per library. Use restrained cinematic motion with reduced-motion support; preserve search, account, server status, mobile, authentication, and existing behaviors. Source: design interview and final user confirmation, 2026-09-11.

- `D-037` — The legibility floor for operator-palette roles lives in the server derivation, not in the components: `internal/gateway/theme.go` derives distinct, contrast-checked values per semantic role (`muted` clears 4.5:1 against the background; `line`, `surface-active` and the text they carry are never identical), so a host Omarchy theme that collapses several roles onto one swatch cannot render unreadable text. The endpoint shape, the host as the palette source, the public read-only route and the built-in fallback all stay as D-020 fixed them; this bounds the derivation, it does not change the contract. Source: user answer Q-025, 2026-09-17.

- `D-038` — The player's preparation overlay shows an honest, bounded wait: elapsed time derived from the server's already-public `started_at`/`queued_at` (a reload must not restart the story), copy naming the first play and the multi-minute cost of sources that need a full re-encode (AV1/HEVC), an explicit statement that leaving continues preparation server-side, and a leave/back affordance. Web-only: no dependency, no server change, no contract change. Source: user answer Q-026/A, 2026-09-17.

## Observability

## Transcode evolution

- `D-028` — Add asynchronous transcoding as `lain.playback.transcode@2` while retaining the synchronous `@1` contract and GET endpoint. Playback inspection is side-effect free and reports an opaque session plus `idle|queued|running|ready|failed`; only an authenticated POST starts or joins work, and an item-scoped status endpoint exposes state without filesystem paths. Source: user answer Q-017/A + advisor triage, 2026-09-13.
- `D-029` — Bound ready transcode artifacts with a plugin-private 20 GiB LRU cache, configurable by `--transcode-cache-size` / `LAIN_TRANSCODE_CACHE_SIZE`. Metadata uses atomic sidecars; cleanup runs at startup and around admission/completion, excludes active artifacts, and removes stale-source and abandoned-temporary entries without coupling the plugin to library deletion. Source: user answer Q-018/A + delegated engineering choice + advisor triage, 2026-09-13.
- `D-030` — Browser compatibility becomes probe-driven and applies equally to anime, movies and series: direct-play only verified web-safe streams; otherwise produce one conservative SDR H.264/AAC MP4, with selected stream identity in the session/cache key. Add selectable audio first, then convertible text subtitles as WebVTT sidecars; reject HDR and unsupported subtitle tracks explicitly until separately scoped tone-map/burn-in profiles. Source: user-delegated engineering choice Q-019 + advisor triage, 2026-09-13.
- `D-031` — Keep progressive MP4 with HTTP Range as the delivery protocol. HLS/DASH, ABR ladders and hardware acceleration stay deferred; future hardware support must be explicit operator opt-in with capability probing and visible software fallback, never silent opportunistic switching. Source: user-delegated engineering choice Q-020 + advisor triage, 2026-09-13.

- `D-039` — `lain.playback.transcode@2` gains one additive status field, `progress` (0..1, omitempty), present while a job runs; no version bump and no server-side ETA promise — the client derives elapsed time and pace from deltas. The field is additive but the @2 payload had been fixed by D-028, so it ships only under this explicit answer. Source: user answer Q-027/A, 2026-09-17.
- `D-040` — The AV1 wait is not paid by weakening the frozen profile: `web-mp4-sdr-v2` / `veryfast` / software-only stays exactly as D-030/D-031 fixed it. The wait is instead reserved to its own slice, authorized but not started: browser-capability direct play, where the client reports decoder support and a verified source remuxes (AV1/Opus into MP4 plus a WebVTT sidecar) instead of re-encoding. That slice needs its own plan before any code. Source: user answer Q-028/C, 2026-09-17.
- `D-041` — Preparation stays play-triggered: only the player's authenticated POST starts work (D-028 intact); no details-page CTA and no proactive warm after scan. Source: user answer Q-029/A, 2026-09-17.

## Transcode expansion (Jellyfin parity)

- `D-042` — Reopen D-031 and D-030 for the full Jellyfin-parity transcode slice: HLS delivery (fMP4 segments, playlists, throttling, segment deletion) alongside the retained progressive MP4, multiple configurable quality profiles, and hardware acceleration. Hardware stays bound by D-031's policy: explicit operator opt-in, capability probing, visible software fallback, never silent opportunistic switching. Per-user playback limits (allow video/audio transcoding, allow remuxing, max bitrate) and transcode-reason reporting are in scope. D-040 (browser-capability direct play) remains reserved with its own plan; live TV/DVR and music/audiobooks stay out per D-016, and trickplay stays in the thumbnail subsystem. Source: user answer Q-030/A, 2026-09-17.
- `D-043` — The web player gains HLS playback through `hls.js`, a web-only runtime dependency (native HLS first on browsers that support it); the Go server adds no dependency (D-001 untouched) and ffmpeg stays an external binary (D-023). Source: user answer Q-031/A, 2026-09-17.
- `D-044` — The expanded transcode session ships as `lain.playback.transcode@3`, retaining `@1` and `@2` unchanged: session options (quality/resolution/bitrate caps, audio and subtitle selection, subtitle mode, delivery) and richer status (encoder, hardware, software-fallback reason, transcode reason, playable-before-complete). Source: user answer Q-032/A, 2026-09-17.
- `D-045` — Runtime transcode settings persist as JSON in the bbolt `meta` bucket through `internal/kv`; `internal/store` stays operator-flag/legacy configuration. An admin-gated `GET/PUT /api/admin/settings/transcode` uses stdlib method patterns; the gateway resolves settings and passes them inside the contract input, so the plugin never reads the bucket or holds HTTP/process-global state (D-006). Any setting that changes output identity enters the session/cache key. Source: advisor triage 2026-09-17 (Q4 answered), cites D-003/D-004/D-006/D-011.
- `D-046` — Complete the Jellyfin encoding surface on the shapes D-044/D-045 already approved, under the user's mandate ("all the features it proposes for transcoding, including advanced interface configuration"): `TranscodeSettings` gains `thread_count`, `max_muxing_queue_size`, `transcode_temp_path`, `remote_bitrate_limit_kbps`, per-codec `h264/h265/av1_preset` and `_crf` (empty/0 inherit the general values), `audio_vbr`, `downmix_audio_boost`, `downmix_stereo_algorithm`, `fallback_font_path`/`fallback_font_name`, `deinterlace_double_rate` and `hardware_decode_10bit_hevc`/`_vp9`; `TranscodeV3Status` gains the live `fps` and `output_bitrate_kbps` D-044 called "richer status"; `auth.PlaybackPolicy` gains `max_streams` and `subtitle_mode`, with `max_streams` enforced inside the plugin (it only compares opaque user ids) and surfaced as `too-many-streams`/429. The downmix algorithm ships as `none` plus a **lain-owned** nightmode matrix, explicitly not Jellyfin's Dave750/NightmodeDialogue coefficients; the temp path relocates artifacts to `<path>/lain-transcode/<session>/` while sidecars stay in the data dir, and cleanup sweeps only that owned subdirectory (D-004/D-006/D-029 respected). `throttle_ahead_sec` is Jellyfin's throttle delay expressed as a produced-ahead budget, so no duplicate knob was added. NOTE: the advisor subagent could not be consulted for this checkpoint — two attempts failed on the configured model's billing ("Insufficient balance"), not on the wiki. The extension is therefore recorded here for human review; it changes no frozen payload (`@1`/`@2` untouched) and every new knob is validated, documented in `docs/CONTRACTS.md`, and covered by tests. Source: user mandate in this thread + D-042 scope answer, 2026-09-17.
- `D-047` — Close the last gaps found in the second audit pass, still inside the approved `@3` shape: (a) on-the-fly subtitle extraction — `@3` gains a `subtitles` action and a sidecar-only delivery kind, so `GET /api/items/{id}/subtitles?stream=N` serves WebVTT for a **directly played** file without transcoding it (Jellyfin's "allow subtitle extraction on the fly"), gated by the new `allow_subtitle_extraction` setting (nil/absent = on, explicit false → `forbidden`); image-based tracks stay `unsupported-media`. (b) `allow_video_stream_copy`/`allow_audio_stream_copy` mirror Jellyfin's client-side `PlaybackInfo` flags, forcing a re-encode of that stream and entering the session identity, with the outcome reported per stream as `video_direct`/`audio_direct` (Jellyfin's `TranscodingInfo` `IsVideoDirect`/`IsAudioDirect`). (c) `deinterlace_method` chooses `yadif` (default) or `bwdif`, degrading to `yadif` with a visible fallback note when the build lacks bwdif. A sidecar-only cache entry is a first-class cache entry: same LRU, staleness judged on the `.vtt`, `playable:false` and `method:"extract"`. The advisor subagent remained unreachable for this pass as well (same model-billing failure), so this is recorded for human review; no frozen payload changed. Source: user mandate in this thread, second audit pass, 2026-09-18.
- `D-048` — The gateway signs HLS media URIs, not the plugin: serving `index.m3u8` rewrites the `EXT-X-MAP` URI and every segment line to carry `session` and the caller's `token`. A relative URI inside an m3u8 drops the playlist's query string, so `hls.js` and native Safari fetched `init.mp4`/`segNNNNN.m4s` unauthenticated and every request returned 401 — the shipped HLS delivery never actually played in a browser. Keeping the rewrite in the gateway preserves D-006 (the plugin never handles tokens or HTTP) and D-043 (no new dependency), and the `?token=` model is unchanged. Found by the real-Chromium e2e, which now asserts playlist + fMP4 segment + advancing playback, plus a Go regression test. Source: audit of the D-047 pass, 2026-09-18.
- `D-049` — Two defects in the D-046 hardware/temp-path surface are fixed, both inside the approved `@3` shape and with no contract change: (a) enabling hardware acceleration **without** hardware encoding was a no-op — `chooseEncoder` reports the encode backend, so a decode-only plan carried `hwBackend == ""` and `hwaccelInputArgs` emitted nothing while the plan and status still claimed hardware decode; the decode hwaccel now comes from the configured backend, the runtime software fallback covers decode-only failures, and the status names the backend actually in use. (b) `artifact_root` already carried the `lain-transcode` namespace, so reopening a finished relocated session from its sidecar resolved a doubled `lain-transcode/lain-transcode/<session>` path; `pathsFor`/`pathsForEntry`/`removeArtifacts` now share one meaning for the owned root. Both were found by the subagent tests (one of which had been skipping), and D-031's visible-fallback discipline is preserved. Source: audit of the D-047 pass, 2026-09-18.
- `D-050` — Two Jellyfin-documented hardware options complete the D-046 surface, with no frozen payload touched: `hardware_device` (default `/dev/dri/renderD128`) names the VA-API render node and feeds both the capability probe and the `-hwaccel_device` argument, so a host whose render node is not the default can use its GPU; and `rkmpp` joins the backend list, matching Jellyfin's documented acceleration methods (VA-API, NVENC, QSV, AMF, V4L2, VideoToolbox, RKMPP). The device is operational, not output-affecting, so it stays out of the session identity (D-045); both are probed with a real one-frame encode and stay unavailable where the local ffmpeg lacks them (D-031). Source: audit against Jellyfin's transcoding docs, 2026-09-18.
- `D-051` — The visible software fallback must clean the burn-in filter graph too: `softwareFallback` stripped `hwupload`/`format=nv12` from `plan.filters`, but the image-subtitle path bakes those tokens into `plan.complexFilter`, so a VA-API session that both burns in an image subtitle and fails its hardware attempt retried with the hardware upload chain and failed again. The tokens are now stripped from both chains, so the fallback stays visible and effective (D-031). Found by an adversarial subagent test that had been skipping; the test now asserts. Source: audit of the D-049/D-050 pass, 2026-09-18.
- `D-052` — Independent adversarial subagent passes over the plugin, gateway, browser player, contracts and coordinator lifecycle found and fixed a series of real defects without touching any frozen payload: an HLS session longer than the v1-era one-hour preparation deadline was killed and had its directory deleted under the player (HLS now runs on an unbounded context, ending by finish/cancel/idle); a second start wiped live sessions' directories under a configured temp path (the orphan sweep now excludes active sessions and claims the shared root with an `.owner` marker); the persisted `queue_size` was a no-op (admission now adopts it); a client-supplied out-of-range segment index paused ffmpeg permanently (the gateway records a position only for a segment that exists, and an out-of-range index means caught-up); a cached-ready HLS session was replayed as progressive and 409'd (the player learns the delivery and attaches hls.js); and a per-user policy was bypassed by cached sessions, by joining a live session, and by the v1 compatibility path (all three now re-check the policy, and a capped account is downgraded from direct play to a capped transcode). Every fix carries a regression test; the client-side one was proven by reverting it. Source: adversarial audit passes 1–8, 2026-09-18.
- `D-053` — Three Jellyfin-documented options complete the encoding surface, additive and inside the `@3` shape (no frozen payload touched): `hls_segment_container` (`fmp4` default, CMAF with an init segment; or `mpegts`, classic `.ts` with no `#EXT-X-MAP`), `hardware_low_power` (QSV's low-power H.264/HEVC encoder, honoured only by QSV), and the AV1 preset now reaches the argv (it was exposed and validated but hardcoded). `TranscodeProfileKey` gained the output-affecting inputs it was missing — `hardware_decode_codecs` and `ffmpeg_path` — while the VA-API render device stays operational and out of the key (D-045/D-050). Everything is probed with a real ffmpeg where the local build allows it. Source: Jellyfin feature-parity audit, 2026-09-18.
- `D-054` — Hardware (VPP) tone mapping is **deliberately not implemented**, and the gap is documented in `docs/CONTRACTS.md` rather than shipped unverified. Concrete evidence from the local ffmpeg: `vpp_qsv` exposes **no `tonemap` option** (only deinterlace/denoise/detail/procamp/crop/scale), so Jellyfin's QSV chain (`vpp_qsv=tonemap=1`) cannot work here regardless; and `tonemap_vaapi` needs VA-API device/frame plumbing (`-init_hw_device`/`-filter_hw_device`, or hwaccel-surface frames) that cannot be validated without a device (the probe finds no backend on the dev host). A wrong chain would fail at runtime and then hit the same fallback-stripping pitfall as D-051 (the software retry must replace the hardware filter, not replay it). The software `zscale`+`tonemap`/`libplacebo` chain already produces correct SDR output, so the missing feature is speed, not correctness. Source: user mandate "all features" + the honest-limitation discipline, 2026-09-18.
- `D-055` — Three corrections close the last documented gaps of the D-042 transcode slice; none touches a frozen payload or the `@3` shape. (a) The served HLS playlist dropped the `#EXT-X-DISCONTINUITY` ffmpeg wrote — the parser even attributed it to the *previous* segment, where HLS places it *before* the segment that starts the new timeline — so a client could stitch across a timestamp jump; the tag is now attributed to the following segment and re-emitted between segments (and dropped when segment deletion moves that boundary to the front of the playlist, where nothing precedes it to be discontinuous from). (b) `position` was a high-water mark, so after a rewind ffmpeg kept racing ahead and the deleter removed the very segments the client was about to re-fetch; the latest report now wins, matching Jellyfin's use of the reported playback position. An out-of-order report can only make the position older, which errs toward pausing sooner and keeping more segments — never toward deleting or racing ahead of the viewer, so the ordering robustness the high-water mark bought is not lost. (c) The browser direct-play profile accepted only AAC audio inside MP4; MP3 is equally web-safe and now direct-plays too, while AC-3/E-AC-3 stay excluded because Chromium on Linux cannot decode them (D-030's "verified web-safe streams"). Each fix carries a regression test that was proven to fail with the fix reverted. Hardware (VPP) tone mapping stays deliberately unimplemented per D-054. Source: user instruction "faça as correções" on the reported gap list, 2026-09-19.
