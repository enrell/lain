local-first media server

lain

Your data. Your machine. Your rules. Your plugins.

A local-first media server written in Go: stdlib-first, no cgo, one static binary. A tiny core hosts replaceable plugins for sources, catalog, playback, search, metadata and everything else that can be optional.

Go · no cgo · single static binary · Apache-2.0

## Features

Everything beyond the tiny core is a plugin: installed, swapped or left out. The server stays useful either way.

  • [core]

    Replaceable plugin core

    A capability registry with generation-fenced runtime swap, so providers can be replaced without restarting the server.

  • [source]

    Filesystem source + identify

    Enumerate media from filesystem paths, then identify anime or generic filenames into structured items.

  • [catalog]

    Catalog, progress & search

    A Bolt-backed catalog with user progress stored separately, plus substring search with replaceable ranking.

  • [stream]

    Direct-play streaming

    Media bytes served over HTTP with Range support, from the same process as the API and the web UI.

  • [playback]

    Playback planner

    Plans direct-play versus transcode-required per request, and stays honest when no transcoder exists.

  • [metadata]

    Metadata enrichment

    Local NFO files plus Kitsu, AniList and Jikan remote providers, merged merge-many and cached with TTLs.

  • [thumbnail]

    ffmpeg thumbnails

    A GET /api/items/{id}/thumbnail transform, cached on disk. Without ffmpeg, the capability degrades honestly.

  • [admin]

    Admin surfaces

    Libraries, scans, users, plugin swaps and online backup. Reads and watching are for everyone; management is admin-only.

  • [web ui]

    Embedded web UI

    A Svelte 5 SPA compiled into the Go binary, served from the same process and origin as the API.

## Install

Three ways in. Docker is the quickest; the static binary keeps it minimal; the interactive installer walks through server and desktop.

Docker

recommended

The image contains the server and the embedded web UI. Keep the database in a named volume and mount your media read-only — users only need the image plus a compose file.

docker run -d --name lain -p 9360:9360 \
  -v lain-data:/data \
  -v ~/Videos:/media/videos:ro \
  ghcr.io/enrell/lain:latest

Then open http://127.0.0.1:9360 for first-run setup. The interactive installer below can also generate a docker-compose.yml for you.

Static binary

Static binaries are published per release. Download the one for your platform and run it — no runtime, no Node, no service to install.

./lain serve --port 9360

Releases on GitHub →

Interactive installer

An interactive Linux script. It asks what you want — server + desktop, server only or desktop only — whether to use Docker or a CLI/daemon service, and where your media lives.

Find it in the lain repository.

## How it works

A tiny trusted core, everything optional behind named capabilities.

lain is a small trusted core surrounded by replaceable plugins. Every optional part of the server — source, identify, catalog, progress, playback planning, search, metadata, thumbnails — sits behind a named capability, and callers only talk to the registry.

Capabilities fan out in one of four modes: exactly-one, ordered-many, first-accepted or merge-many — as when local NFO, Kitsu, AniList and Jikan metadata are merged.

Providers are swapped at runtime: candidates are health-checked first, every request is fenced by generation so a stale writer cannot overwrite newer state, and a provider that fails at call time falls back to the last-good one, once.

Nothing optional is hardcoded. When a provider is missing, the feature degrades honestly and the core keeps doing its small trusted job.

+--------------------------------------------------+
|                    lain core                     |
|          registry . generations . auth           |
+-------------------------+------------------------+

       resolve capability (generation-fenced)
                          |

  swap: source@1 -> source@2  (health-checked, last-good fallback)

## API

The same process serves the JSON API, media bytes and the embedded UI. Authenticate once; reads and progress are for every user, admin routes are gated.

  • GET /healthliveness and database health
  • POST /api/setupcreate the first admin
  • POST /api/auth/loginobtain a bearer token
  • GET /api/catalogpaged catalog: limit, offset, sort, library_id
  • GET /api/search?q=substring search
  • GET /api/items/{id}/playbackdirect-play or transcode-required plan
  • GET /api/items/{id}/streamdirect play over HTTP Range, with a ?token= fallback
  • GET /api/items/{id}/thumbnail?t=&w=ffmpeg still, cached on disk
  • PUT /api/items/{id}/progressresume state, written in bounded intervals
  • GET /api/plugins POST /api/plugins/swapinspect and swap capabilities (admin)
# log in — the response contains a bearer token
curl -X POST http://127.0.0.1:9360/api/auth/login \
  -d '{"username":"admin","password":"change-me"}'

# substring search
curl "http://127.0.0.1:9360/api/search?q=frieren" \
  -H "Authorization: Bearer $TOKEN"

# stream with Range — any HTTP player, e.g. mpv
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:9360/api/items/<id>/stream"

# swap a capability in place, no restart
curl -X POST http://127.0.0.1:9360/api/plugins/swap \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"capability":"lain.media.identify@1","providers":["lain-identify-generic"],"generation":1}'
